Hugging Face trending models: which inference engine can run them?

Top 200 from huggingface.co/models?sort=trending, classified by task (pipeline_tag) and mapped to a serving engine. Data from the HF API (sort=trendingScore). Snapshot: May 2026. Companion to the OpenRouter report, same infaas lens (vLLM + Triton).

Bottom line: unlike OpenRouter (which is ~99% chat LLMs), Hugging Face trending is deeply multimodal. Generative text + vision-language models are the largest slice, but image/video generation, speech, and classic CV together are nearly half the list. So vLLM alone serves only ~56% of HF trending. The rest needs a diffusion stack, a speech stack, and Triton for classic CV. A real platform here is multi-engine: vLLM + Triton + diffusers + a Whisper/NeMo speech path.

VLM = vision-language (image-text-to-text), LLM = text-generation, Embed = feature-extraction/similarity, Diffusion = image/video generation, Speech = ASR/TTS/audio, Vision/Other = classic CV + uncategorized, Omni = any-to-any.

2. Engine coverage

What share of the 200 each serving stack can run. No single engine covers everything: this catalog is multimodal by nature.

vLLM (LLM+VLM+embed)
56%
Triton (multi-backend*)
~78%
diffusers / ComfyUI
20%
Whisper / NeMo (speech)
11%
TEI (embeddings/rerank)
~5%

* Triton is a multi-backend router: it natively serves LLM/VLM (via its vLLM backend), classic CV and encoders (ONNX/PyTorch), and can wrap diffusion/speech models through its Python backend, though that wrapping is custom work rather than turnkey. The ~78% reflects what is practical out of the box; with Python-backend effort it approaches 100%.

vLLM lane (~56%)

  • text-generation (51) and image-text-to-text VLMs (55): the bulk, all decoder LLMs/VLMs.
  • embeddings / sentence-similarity (5): vLLM pooling mode or TEI.
  • Same engine family as the OpenRouter report. SGLang / TGI / TensorRT-LLM are alternatives.

Everything vLLM can't do (~44%)

  • Diffusion (41): text-to-image, image/video generation. Needs diffusers or ComfyUI.
  • Speech (22): ASR (Whisper/Parakeet), TTS, audio gen. Needs faster-whisper / NeMo / specialized.
  • Classic CV + encoders (22): detection, segmentation, classification, BERT-style. Triton ONNX/PyTorch.
  • Omni (4): any-to-any models, partial vLLM support, often specialized runtimes.

OpenRouter is an inference-API marketplace, so its catalog is almost entirely text-generation. HF trending reflects the whole open-model research frontier, where image/video generation and speech are first-class, hence the much broader engine requirement.

5. Recommendation for infaas

  • vLLM remains the primary engine and covers the single biggest slice (text + vision-language, ~56%).
  • Triton is essential here, not optional, as the multi-backend home for classic CV, encoders, and as a wrapper for diffusion/speech via its Python backend.
  • Add a diffusion path (diffusers / ComfyUI) and a speech path (faster-whisper / NeMo) if you want to serve the trending frontier, together that is ~31% of the list that neither vLLM nor a plain Triton ONNX backend handles turnkey.
  • No "API only" gap: every HF model is open-weight, so coverage is purely an engine-capability question, not a licensing one.
